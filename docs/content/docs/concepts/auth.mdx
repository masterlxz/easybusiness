title: Authentication
description: Static API keys via the X-API-Key header.
---

Every endpoint requires an `X-API-Key` header. There's no OAuth, no per-consumer key table, no
rotation mechanism yet — this is a deliberate MVP choice, not an oversight.

```bash
curl -H "X-API-Key: your-key-here" http://localhost:8000/v1/macro-series/cdi
```

A missing or unrecognized key returns `401 Unauthorized`:

```json
{ "detail": "Invalid or missing API key" }
```

## Configuring keys

Keys are a comma-separated list in the `API_KEYS` environment variable (`api/.env`):

```bash
API_KEYS=key-for-anchor,key-for-some-other-consumer
```

Any value in that list is accepted — there's no way (yet) to tell which consumer made a given
request, scope a key to specific endpoints, or revoke one without redeploying. That's a known
limitation, not the final design — see the project's `ARCHITECTURE.md` for the tracked decision.
